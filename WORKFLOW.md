# WORKFLOW — порядок выпуска шорта

Папка выпуска: `episodes/NNN-имя/` (первый выпуск лежит в `episodes/garcia-benn/`, новые называть `002-имя` и дальше). Файлы выпуска: `script.ru.txt`, `plan.md`, `annotations.json`, `timeline.json`, `schedule.json`, `voice/` (mp3 в git не идёт). Шаблон: `episodes/_template/`.

Общее правило: **пользователь пишет «да» (или «делай») перед озвучкой и перед полным рендером.** Всё до этого можно: кадры, планы, пробные рендеры 2–3 с, `voice.mjs --plan`. Перед работой прочитать `FORMAT.md` и `LESSONS.md`.

Команды ниже запускаются из корня репозитория. `npm install` один раз за сессию; `npm run selftest` проверяет инструменты.

## 0. Клип
- Что делать: пользователь прикладывает файл в сессию (так видео доходит). Положить в `clips/<имя>.mp4` (в git не идёт). `node -e "import('./tools/lib/common.mjs').then(m=>console.log(m.probe('clips/<имя>.mp4')))"` — размер, fps, длительность.
- Проверять: сколько длится клип на самом деле (в первом выпуске обещали «около 7 минут», пришло 82,6 с, потом «около минуты»).
- Стоп: не нужно, если длительность понятна. Если клип не тот, что обещано, сказать сразу.

## 1. Поиск момента
- Команда: кадры раз в 3 с шириной 320 px, листы по 16 кадров с подписью времени (`ffmpeg ... fps=1/3,scale=320 ... tile=4x4`), смотреть листы, а не весь клип.
- Проверять: есть ли плашка с таймером раунда (даёт таймкоды и подтверждает, что клип непрерывный) и плашка с именами бойцов (бойцов определять по ней, не по цвету трусов).
- Результат: 3–5 моментов по 10–35 с, что происходит и почему подходит. **Стоп: ждать выбора.**

## 2. Плотные кадры контакта
- Команда: `node tools/frames.mjs clips/<имя>.mp4 --from A --to B --every 0.1 --out work/frames --grid 4 --tile 480`; для серии подряд кадров на 1/30 с использовать `-ss` по одному кадру; для мелочи `--crop x:y:w:h`.
- Проверять: смотреть сами кадры, не только лист. Найти кадр контакта, смену камеры (резкий скачок разности кадров; на смене координаты ломаются), какой ракурс непрерывен.
- Записать в `plan.md`: что видно, что не видно (рука, куда попал, как стоял соперник). Не видно значит «не видно».
- Стоп: если удар не определяется, сказать об этом и предложить другой момент.

## 3. Сценарий
- Файл: `episodes/NNN-имя/script.ru.txt`. Одна строка = одна реплика (до 12 слов), одна мысль, по ударам. Структура по `FORMAT.md`: хук, что видно до удара, удар, результат, вывод. 30–40 с.
- Проверять: имена (Райан Гарсия, Конор Бенн) пишутся вручную, не транскрибируются; руки не называть, если кадры её не показывают; не писать «остановил бой», «встал» без кадра или решения автора. Считать слова и знаки (`node tools/voice.mjs episodes/NNN-имя --plan`).
- Стоп: **показать сценарий, таймкоды, 3–4 крупных кадра контакта и план разметки, ждать «да».**

## 4. Разметка и план сегментов (без озвучки)
- Файлы: `annotations.json` (формат `docs/ANNOTATIONS.md`), `timeline.json` (сегменты: `from`, `to`, `factor`, `cx`, `annotations`), `schedule.json` (старт каждой реплики, секунды ролика).
- Как: координаты брать по кадрам с сеткой (`drawgrid` 50–100 px), не на глаз; рамка на голове цели, стрелка с `track` по ключам кулака, звезда в кадре контакта. Только там, где контакт определён.
- Проверять: смену камеры внутри сегмента (сегмент заканчивать до неё), перекрытие головы рукой (рамку там не ставить).

## 5. Озвучка (после «да»)
- Команды: `node tools/voice.mjs episodes/NNN-имя --plan`; тест одной реплики `--only 1`; потом всё. Нужные ключи: `--keys 8,9`. Голос `--voice N` (`voices.json`).
- Проверять: что озвучены только изменившиеся реплики (кеш по хешу текста и голоса), тайминги пришли от API (`source: elevenlabs` в `voice/NNN.align.json`), реплики встают по `schedule.json` без наложений (инструмент падает при наложении). Остаток кредитов по ключам: счётчик API отстаёт на минуты.
- Стоп: перед озвучкой показать, какие фразы озвучатся заново, сколько знаков, остатки по ключам. Звук я не слушаю: просить пользователя прослушать.

## 6. Рендер (после «да»)
- Команда: `node tools/build-short.mjs episodes/NNN-имя --keep --resume` (`--resume` берёт готовые сегменты; чтобы пересобрать сегмент, удалить `work/short/NNN-имя/<id>` и запустить снова). Выход: `out/NNN-имя.mp4`.
- Проверять: длительность сходится с расписанием (вывод build-short: «длительность склейки отличается» допустимо до ≈0,2 с), звук и видео одной длины (`ffprobe`), субтитры из `script.ru.txt` (инструмент падает, если слова не совпали).

## 7. Проверка по кадрам
- Команды: `node tools/verify.mjs work/short/NNN-имя/<сегмент>/slow.mp4 .../ann.mp4 .../annotations.json`. Он проверяет только, что нарисованное стоит там, где написано в json.
- Глазами: крупные вырезки (`crop=420:320`, ×1,5–2) кадров контакта с наложением и без него: остриё стрелки на цели в контакте, рамка охватывает голову, звезда на месте. Не совпало: поправить координаты, пересобрать сегмент, снова смотреть. В `plan.md` записать, какие кадры смотрели.
- Не писать «исправлено», пока не посмотрел кадр.

## 8. Показать и выложить
- Показать: файл шорта и 4 кадра (хук, контакт, добивание или результат, финал), длительность числом.
- Коммит и пуш текстов и инструментов (`git add -A`, проверить `git ls-files | grep -Ei '\.(mp4|mov|mp3|wav)$'` — пусто). Видео и озвучка в git не идут.
- В конце ответа: что проверено, что нет. Стоп: ждать правок.

## 9. Закрытие выпуска
Делать после того, как автор принял шорт (или сказал закрывать). Порядок:
- (а) **Смержить ветку в main и запушить**, без force. Если конфликт, показать его и остановиться. Показать `git log main --oneline` (5 последних).
- (б) **Проверить, что видео, mp3 и кадры не в git:** `git ls-files | grep -Ei '\.(mp4|mov|mp3|wav)$'` — пусто.
- (в) **Дописать `LESSONS.md`:** что узнали, в чём ошиблись, что проверили, а что нет. Не удалять старое.
- (г) **Записать в `episodes/NNN-имя/RESULT.md` итог:** название (варианты и выбранное), длительность числом, голос и `voice_id`, ключ и остаток кредитов (`node tools/voice-check.mjs --balance`, счётчик API отстаёт), что не удалось или не проверено.
- (д) **Предложить автору 1–2 улучшения для следующего выпуска** из `IMPROVEMENTS.md` (по одному на выпуск), с оценкой, что нужно доделать в инструментах. Не делать их без «да».
- В конце ответа: что проверено, что нет.

## 10. Лонг 16:9 (профиль wide, с выпуска 003)
- Структура: `episodes/003-long/long.json` (`chapters: [{id, title}]`), каждая глава — каталог `chNN/` с `timeline.json`, `script.ru.txt`, `schedule.json`, `voice/`, `annotations*.json`.
- Инструменты: `tools/wide.mjs` (1920×1080, lanczos), `build-short.mjs --profile wide` (одна глава; сегмент `{"blank": секунды}` — карточка; метка главы добавляется автоматически), `subs.mjs --mode phrase` (субтитры фразами внизу), типы разметки `plaque` («по данным прессы») и `chapter`, `tools/build-long.mjs` (главы → один файл, `--chapter 3,4` собирает только эти главы, `--loudnorm`).
- Разметка пишется в пикселях исходного клипа (1280×720); `build-short` сам умножает координаты на 1,5.
- Исключение для git: `episodes/003-*/…/voice/*.mp3` (синтетический голос) хранится в git; видео, кадры, клипы боёв — нет. Проверка: `git ls-files | grep -Ei '\.(mp4|mov|wav)$'` — пусто; mp3 допустимы только в `episodes/003-*/voice/`.
